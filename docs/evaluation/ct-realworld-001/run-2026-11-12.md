### Verified before/after correction

Commit `5171ff4` narrows call-binding error taint to a function declaration's
header/signature instead of its entire body. On the three-call project
regression, temporarily rebuilding the pre-fix extractor made all three exact
calls unresolved and the test failed (`exit 1`). Rebuilding the candidate
extractor made all three exact and the same test passed (`exit 0`). The two
unrelated `TS_2322` body diagnostics remained. This verifies the focused
regression; repository-wide accuracy remains unmeasured.

The self-browser runner also exposed a test timing race: it inspected the DOM
immediately after the HTTP response, before the viewer rendered the completed
graph. Direct analysis contained the exact pinned `analyzeProject` call at
`project.ts:31`; adding a bounded wait for the expected source/target row made
the 2/2 self-browser workflows pass. The change is confined to the evaluation
runner; product behavior stays unchanged.

## Comparison and bottleneck ranking

The scripted terminal comparator completed the same **15 tasks / 28 labels**
using 42 `git grep` / `git show` commands. Per-repository lookup plus anchor
validation took 435 ms for Hono, 404 ms for Zod, and 535 ms for Pinia. These
times cover Git commands and anchor validation; they exclude human reading and
comprehension and cannot establish developer effectiveness.

1. **Zod profile remains near its deadline.** The raised bounded profile
   analyzed all source files once in 114.7 s, but two project configs are
   invalid and the run had only 5.3 s observed deadline headroom. The five fixed
   Zod browser tasks completed in the selected build context; this does not
   establish general repository capacity or semantic correctness.
2. **Incomplete project context across all repositories — broad scope.** Hono
   had four non-ready contexts, Zod five, and Pinia five. `contextComplete` was
   false for all three repositories. The tested tasks do not establish complete
   workspace/project understanding.
3. **Supported syntax coverage — material semantic limit.** The semantic fixture
   contains 13 unsupported cases out of 30; exactness is perfect only within the
   smaller scored supported denominator. The browser task set had no wrong-exact
   or supported misses; arbitrary TypeScript syntax remains outside this
   evaluation.
4. **Evidence quality — blocks the developer-benefit conclusion.** Labels are
   AI-authored and lack independent human review; the Git comparator measures
   command latency rather than people. No participant study was run.
